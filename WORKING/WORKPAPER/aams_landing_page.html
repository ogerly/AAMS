Warum AAMS deinen Workflow verändert

Vergleiche die tägliche Arbeit mit KI-Agenten vor und nach der Einbindung des AAMS-Manifests.

Ohne AAMS

Der Kontext verfliegt mit jeder Session

  • Verlorener Kontext: Jede neue Session startet bei Null. Die KI hat keine Ahnung, was gestern besprochen wurde.
  • Halluzinierte Entscheidungen: KI-Tools stellen dieselben Fragen mehrfach oder überschreiben gegenseitige Vereinbarungen.
  • Vendor Lock-In: Chat-Protokolle sind in proprietären Datenbanken von Cursor, Copilot oder ChatGPT gefangen.
  • Chaos im Root-Ordner: Hilfsskripte, Notizen und Agenten-Output vermischen sich ungeordnet mit deinem Source Code.

Mit AAMS/2.4.0

Lokal verankertes Projektgedächtnis

  • Lückenloses Gedächtnis: Jede Session protokolliert in WORKPAPER/ und speichert langfristig im MEMORY/.
  • Klare Architektur-Truth: Architekturentscheidungen versteinern in WHITEPAPER/ und verhindern Halluzinationen.
  • Werkzeug-Souveränität: Egal ob du heute Cursor und morgen Claude Code nutzt – das Wissen bleibt in einfachen Markdown-Dateien im Repo.
  • Geschütztes Repository: Sämtliche Agenten-Notizen liegen isoliert in WORKING/. Keine Vermüllung deines Projekts.

SESSION LAYER

WORKPAPER /

Hier dokumentiert der Agent jede einzelne Arbeitssession. Am Start der Session wird ein neues Workpaper geöffnet und am Ende geschlossen und nach WORKPAPER/closed/ verschoben.

Namenskonvention: WP-{DATE}-{TOPIC}-{SUBTOPIC}-{description}.md
Löscherbot: Niemals überschreiben. AAMS Schema Layer

Session Lebenszyklus

Der AAMS Wissensfluss (Knowledge Chain)

Jede KI-Arbeitssession folgt einem klaren, nachvollziehbaren Lebenszyklus, ohne dass Wissen verloren geht.

01

1. Session Start

Agent liest READ-AGENT.md, prüft alte Workpapers und erstellt ein neues aktives Workpaper unter WORKPAPER/.

02

2. Aktives Arbeiten

Die KI führt ihre Aufgaben im Code aus und protokolliert kontinuierlich geänderte Dateien, Entscheidungen und Logins im Workpaper.

03

3. Whitepaper Update

Bei stabilen Architekturentscheidungen versteinert das Wissen im WHITEPAPER/. Die Architektur-Wahrheit wird aktualisiert.

04

4. Memory Ingestion

Session End: Das Workpaper wandert nach closed/, und Erkenntnisse fließen in den Langzeit-Index ltm-index.md.
